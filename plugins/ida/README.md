# disrobe for IDA Pro

An IDA Pro (IDAPython, Python 3) plugin that surfaces disrobe's recovery inside
the database. It runs the disrobe CLI on the open file (or ingests a previously
saved disrobe `--json` report), parses the recovery report, and applies it to the
IDB: recovered function names at their addresses, capability and IOC findings as
comments, recovered strings, and recovered structs where a report carries them.

It mirrors the disrobe-output ingestion contract of the Binary Ninja plugin
(`editors/binja`): same disrobe subcommands, same `--json` report schemas. Where
the Binary Ninja plugin prints disrobe output to the log, this plugin parses the
machine-readable report and writes the recovery into the database via the IDA API.

## Requirements

- IDA 7.4+ with the IDAPython (Python 3) runtime.
- The `disrobe` binary on PATH, or edit `DISROBE_BINARY` at the top of
  `disrobe_ida.py`.

## Installation

Copy this `ida` directory's `disrobe_ida.py` and `disrobe_report.py` into your IDA
`plugins/` directory (keep them side by side; the plugin imports the parse/map
core from `disrobe_report`). Restart IDA. The plugin loads automatically and adds
actions under `Edit > Plugins`.

## Actions

| Action | disrobe invocation | What it applies |
|---|---|---|
| disrobe: apply native symbols | `disrobe --json native symbols <input>` | recovered function names at their addresses (`set_name` + `add_func` for text symbols) |
| disrobe: apply capabilities | `disrobe --json capabilities <input>` | one comment per matched capability (rule, namespace, description, ATT&CK / MBC tags) plus a comment at each evidence address |
| disrobe: apply strings | `disrobe --json strings <input>` | recovered + deobfuscated strings (offset, tag) listed in the results view |
| disrobe: load saved --json report | a saved disrobe `--json` file | any of the schemas below |

## Supported report schemas

The parse/map core understands these disrobe `--json` report schemas:

| Schema | Carries | Applied as |
|---|---|---|
| `disrobe.native.symbol-map/v1` | `image_base`, recovered symbols (address, name, demangled, class, origin, note) | rebased function names; notes become repeatable comments |
| `disrobe.native.symbols/v0` | object symbol table (name, address, size, kind, section) | function names at their raw addresses |
| `disrobe.capabilities/v0` | capability matches + evidence addresses, ATT&CK / MBC tags | comments at the match and evidence addresses |
| `disrobe.strings/v0` | extracted + deobfuscated strings (value, offset, tag) | results-view listing |

Symbol maps that carry an `image_base` are rebased onto IDA's image base
(`IDA_BASE + (addr - image_base)`), matching disrobe's own IDAPython sidecar from
`disrobe native export --format ida`. Object symbol tables already use absolute
addresses, so they are applied without rebasing.

## Verification

The parse/map core (`disrobe_report.py`) and the application logic
(`apply_annotations` / `render_summary` in `disrobe_ida.py`) are unit-tested
headless against **real** disrobe reports generated by the built CLI:

```
python -m unittest discover -s tests -p "test_*.py"
```

The fixtures under `tests/fixtures/` are real disrobe `--json` output:
`disc.symbols.json`, `disc.capabilities.json`, and `disc.strings.json` were
produced by running the disrobe CLI on `corpus/native/discovery/disc.unstripped.elf`;
`nspack.symbol-map.json` from `disrobe native export --format json` on
`corpus/native/packers/nspack/hash.packed.nspack.exe`. The tests treat each report
as ground truth and assert the produced annotation set (function name -> address,
comments, strings) is faithful to it.

The in-IDA application path (the real `idaapi` / `idc` / `ida_funcs` /
`ida_name` / `ida_struct` / `ida_kernwin` calls in `_LiveIdaAdapter`) is structured
behind a thin adapter so the core is testable without IDA. That live path has not
been load-tested in this environment because IDA is not installed here; it is
verifiable manually once the plugin is loaded inside IDA.
