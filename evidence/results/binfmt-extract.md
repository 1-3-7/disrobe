# Container, archive, firmware, and encrypted-volume extraction

- id: `binfmt-extract`
- ecosystem: binfmt
- claim: disrobe detects 102 container, archive, firmware, and encrypted-volume formats. 101 carry a generic in-tree payload extractor and LUKS1 carries a bounded raw-volume-key route plus a typed keyless wall. 41 generic routes are driven to member bytes on disk by an input this repository commits, and LUKS1 is graded separately against tracked plaintext. The other 60 generic routes have no committed input, so they are unverified rather than shown to fail.
- measured: 41 extracted from a committed input / 102 detected
- oracle strength: coverage-self-reported
- CI-attested: yes [CI]
- evidence basis: the delivered count is disrobe extracting from its own committed corpus and counting the generic formats that wrote bytes, not an independent check. The LUKS1 route is separately compared with tracked plaintext and an independently generated encrypted fixture. Individual format tests may use external byte manifests, but the 60 generic formats with no committed input carry no measurement at all
- reproduce: `cargo test -p disrobe-binfmt published_container_counts_match_this_enum`
- gate source: ContainerKind::ALL in crates/disrobe-binfmt/src/container.rs declares 102 detected variants excluding None, asserted by detected_count_is_one_hundred_and_two. The same file declares 101 generic payload extractors and names LUKS1 as the one metadata-only generic boundary because its dedicated API requires a raw volume key, asserted by every_declared_format_names_its_extraction_boundary. The measured generic leg remains 41 formats driven to member bytes by tracked inputs in crates/disrobe-cli/tests/container_breadth.rs and crates/disrobe-cli/tests/golden/container_breadth.txt. crates/disrobe-binfmt/tests/real_luks1.rs separately grades the LUKS1 route by decrypting a tracked aes-cbc-plain fixture to byte-identical tracked VHD plaintext and entering the VHD extractor; crates/disrobe-cli/tests/luks1_extract.rs grades the file, stdin, keyless-wall, wrong-key, and unsupported-mode surfaces. The remaining 60 generic extractors have no committed input and are unverified rather than shown to fail.
