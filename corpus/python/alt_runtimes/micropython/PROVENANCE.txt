MicroPython (.mpy) fixtures
===========================

hello_bytecode.mpy     real mpy-cross output, default bytecode emitter (mpy v6).
control_flow.py        source: classify(n) with a for-loop, if/else, and string returns.

hello_native.py        source with @micropython.native (add) and @micropython.viper (mul).
hello_native_x64.mpy   real mpy-cross output, x86-64 native emitter (mpy v6, arch x64).
hello_native_armv7m.mpy real mpy-cross output, armv7m thumb native emitter (mpy v6, arch armv7m).
iter_loops.py          source: walk(items) iterating a sequence and counted(n) iterating range(n).

classes.mpy            real mpy-cross output, default bytecode emitter (mpy v6).

closures.mpy           real mpy-cross output, default bytecode emitter (mpy v6).
generators.py          source: yield in a while loop and a for loop, yield from, a generator with a return value.

Origin
------
Compiled in-house with the official mpy-cross (MicroPython v1.27.0, emitting mpy v6.3):
  mpy-cross -o hello.mpy          hello.py
  mpy-cross -o hello_bytecode.mpy hello.py
  mpy-cross -o control_flow.mpy  control_flow.py
  mpy-cross -o iter_loops.mpy    iter_loops.py
  mpy-cross -o classes.mpy       classes.py
  mpy-cross -o closures.mpy      closures.py
  mpy-cross -o generators.mpy    generators.py
  mpy-cross -o exceptions.mpy    exceptions.py
  mpy-cross -o signatures.mpy    signatures.py
  mpy-cross -march=x64    -X emit=native -o hello_native_x64.mpy    hello_native.py
  mpy-cross -march=armv7m -X emit=native -o hello_native_armv7m.mpy hello_native.py

Decompile oracle
----------------
The bytecode fixtures are also lifted onto the CPython decompiler IR (decompile_micropython):
each .mpy function is re-encoded as CPython 3.10 wordcode (qstr/object tables become the
const/name/varname pools, static qstrs resolve via py/makeqstrdata.py's static_qstr_list,
and MicroPython's special-cased `for i in range(n)` counting loop is recognised and
rewritten to the FOR_ITER+range form), then run through the normal structurer. The
recovered source is graded by recompiling it under CPython (it round-trips to valid Python)
and by matching the known sources: hello -> def add + print(add(1, 2)); control_flow ->
def classify with `for i in range(n)`, the if/else body, and the trailing branch; iter_loops
-> walk's sequence for-loop and counted's range for-loop.

Beyond that, tests/alt_runtime_decompile.rs grades every bytecode fixture against mpy-cross
itself: the recovered source is handed back to mpy-cross, the resulting .mpy is decoded, and
every function prelude and opcode step is compared with the committed fixture. All eight
bytecode fixtures agree on every unit. MicroPython stores parameter names in the prelude but
not the names of other locals, of the *args and **kwargs slots, or of closure cells, so those
are regenerated (local3, varargs, varkwargs, cell5) while every parameter, class, method and
function name is recovered. MicroPython also moves a named *args parameter to the end of the
parameter list, so the keyword-only order is unrotated on the way back out.

Bytecode oracle
---------------
mpy-cross is the real MicroPython compiler, so the .mpy bytes are ground truth. The
bytecode decoder walks the v6 container (magic, qstr/object tables, raw-code tree with
the kind_len varuint), unpacks each function prelude (MP_BC_PRELUDE_SIG_DECODE and
MP_BC_PRELUDE_SIZE_DECODE from py/bc.h), then decodes the opcode stream against the
py/bc0.h table with the DECODE_UINT / DECODE_SLABEL / DECODE_ULABEL / signed-small-int
rules from py/showbc.c and the unary/binary-op ordinals from py/runtime0.h. hello's add
decodes to LOAD_FAST a, LOAD_FAST b, BINARY_OP add, RETURN_VALUE, matching the source.

These are benign self-authored payloads (add/mul of two integers) used as the
non-circular disassembly oracle: mpy-cross is the real MicroPython compiler, so the
.mpy bytes and the emitted machine code are ground truth, graded against the real
x86-64 / armv7m-thumb instruction stream.

Format reference
----------------
The .mpy container layout (header, qstr/object tables, raw-code tree with the
kind_len varuint, native fun_data and prelude_offset) follows MicroPython
py/persistentcode.{c,h} and tools/mpy-tool.py for mpy version 6. For a native-py
function the machine code is fun_data[0..prelude_offset]; the entry point is
fun_data[0]; viper/asm functions carry no prelude (the whole fun_data is code).
