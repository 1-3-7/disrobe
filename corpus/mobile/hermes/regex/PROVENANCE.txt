disrobe self-authored Hermes regex-bytecode fixtures
====================================================

Two benign self-authored JavaScript files, each a list of regex literals, compiled
with the real Hermes compiler (hermesc, FOSS, facebook/hermes release binary
hermes-cli-windows from tag v0.13.0). The bytecode is never executed; it is parsed
and the compiled RegExp table is disassembled back to pattern text statically.

Exact build command (per file):

  hermesc.exe -emit-binary -out regexes.hbc.v96 regexes.js
  hermesc.exe -emit-binary -out edge.hbc.v96    edge.js
  hermesc.exe -emit-binary -out nest.hbc.v96    nest.js

Scope of recovery, stated plainly:

  The disassembler reads the RegExp table and per-regex bytecode blob (header plus
  the regex opcode stream) and reconstructs each pattern back to its source text.
  Grading is non-circular: each recovered pattern is asserted against the known
  source regex in tests/real_hermes_regex.rs, not against the disassembler's own
  output. All 31 patterns across the two fixtures reconstruct exactly.

  A few recovered forms differ from the source spelling because the compiler
  rewrites them and the original spelling is not present in the bytecode:
  case-insensitive literals are upcased (a.c with the i flag stores A and C), bracket
  ranges are canonicalized and sorted ([A-Za-z0-9_] stores 0-9 A-Z _ a-z), adjacent
  members are coalesced into ranges ([^abc] stores a-c), and a lookbehind body is
  stored reversed (recovered by reversing simple literal runs). Any regex opcode the
  decoder cannot model is marked rather than guessed: the recovered struct exposes a
  fully_modeled flag that goes false and the pattern is left as decoded so far.
