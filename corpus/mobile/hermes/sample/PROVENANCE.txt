disrobe self-authored benign React Native Hermes bytecode sample
================================================================

Source: sample.js (plain JavaScript, no third-party packages, no network, no
eval). Authored for disrobe regression fixtures. It exercises arithmetic
(add), a counted loop (sumRange), string concatenation (greet), and a class
with prototype methods (Counter.increment / Counter.label), plus an entry
function (main).

Compiler: the real Hermes compiler (hermesc), FOSS, from the official
facebook/hermes GitHub release binaries (hermes-cli-windows). Each .hbc here is
the raw output of `hermesc -emit-binary`. The bytecode is never executed; it is
parsed and lifted statically.

Exact build command (per version, run against the matching hermesc.exe):

Scope of recovery, stated honestly:

  Container parse (header, function table, string and identifier tables) works
  across the committed v76-v96 spread: all three resolve 8 functions and recover
  the real function names add / sumRange / greet / Counter / main / increment /
  label from the module string table.

  Full opcode lifting (bytecode-to-pseudo-JS) is calibrated to the HBC v96
  opcode table, which is the version current React Native ships and the version
  of the production bundle disrobe was built against. On sample.hbc.v96 every
  opcode has a real lowering rule (100% op-coverage, zero fallback) and the
  recovered bodies match the source: add returns arg0 + arg1, greet returns the
  "disrobe-hermes-" prefix concatenation, sumRange recovers its loop, increment
  recovers this.value + 1. The v84 and v76 bytecodes use an older opcode
  numbering, so their instruction bodies do not decode under the v96 table; they
  are committed as evidence of cross-version header/name recovery, not of
  opcode-lift correctness.

  This is a structured lifter, not a full decompiler. Variadic call arguments
  (Call / Construct / CallDirect / CallBuiltin) are marked <arg?> because the
  Hermes frame-register argument block is not modeled; no-op instrumentation
  opcodes (ProfilePoint, AsyncBreakCheck) count as fallback, not reconstruction.
